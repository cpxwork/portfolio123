# 嗨皮瓜后端交接：先跑通一段话的闭环

截至 2026-10-17，这个分支已加入 `server/` 本机真实文本模型服务和前端接入：`GET /api/health`、`POST /api/agent`，模型按需执行四种职责，并显示真实调用记录。它没有发布到腾讯云。下文保留的是公网账号/视频/持久化接口提案；只有上述本机接口已有实现。具体运行协议以 `server/README.md` 为准。

## 先统一产品范围

用户当前确认的是网页里的“记录灵感 → 学习安排 / 创意探索 → 行动反馈 → 下一轮记录”。三种模式是每天可换的陪伴风格：温和、奖励、督促。虫虫只在本页出现，用户选择开启，10 秒内自动清除，也可立即退出。

当前 main 已从 `70a532c` 更新到 [`32a4ff7`](https://github.com/cpxwork/portfolio123/commit/32a4ff7e9e6b05d11c863ff9dad6dd8779bd1690)，新增 `discipline-agent/` 实际代码、测试和演示；不能再描述为“只有计划”。它是独立的自律督促模块，包含提取、状态判断、拆步、督促决策和本地执行，尚无HTTP服务，也未接入本分支的嗨皮瓜网页。2026-10-17独立复跑11套离线/模拟测试全部通过；这不等于真实模型、摄像头或网页集成已验收。完整核查见 `TEAM_REVIEW.md`。

摄像头姿态、桌面移动文件和文件隔离属于该模块另一部分产品范围，当前未接入嗨皮瓜。可以先复用提醒撤回、事件契约和审计思路，按网页接口协议做适配；姿态检测不能代替学习成果视频分析。默认演示使用模拟数据，真实模式须单独配置和验证。

## 你先交付的最小接口

1. `GET /api/health`：本机已实现，返回版本、选定免费模型与实际能力状态；配置存在不等于真实账户已经成功调用。每条成功记录的trace才是执行证据。
2. `POST /api/agent`（兼容 `/api/turn`）：本机已实现，接收原话、已有话题/任务、确认偏好、关联反馈；返回经过校验的analysis/content/trace。前端事务应用，不再跑本地解析冒充模型。公网状态版本与数据库持久化仍待实现。
3. `POST /api/media/analyze`：独立能力。用户明确同意上传之后才能发视频；返回实际看到了什么、证据时间段、局限和下一步建议。没接服务就返回 capability 不可用，不能据文件名生成点评。
4. 跨设备记忆：账号隔离、数据库持久化、查改删/导出与来源。将“用户确认事实”和“有待确认的观察”分开。不要返回永久记忆或确定人格判断。
5. 积分：单独的服务器账本，见下文。先不实现真实抵扣，不耽误文本闭环上线。

## 文本接口提案

前端入口现在是 `web/index.html` → `studio.js`（界面）和 `studio-core.js`（存储/业务）。`app.js` 是保留的旧界面，不再加载。`engine.js / ramble.js / pocket.js` 是本地规则，由前端负责人维护，后端不要并行重写。

```json
{
  "requestId": "client-generated-uuid",
  "sessionId": "opaque-session-id",
  "expectedStateVersion": 12,
  "text": "我想学画画，明天中午十二点练十分钟。另外我想做一个小网站。",
  "timezone": "Asia/Shanghai",
  "mode": "gentle",
  "confirmedPreferences": {"duration": 10, "energy": "medium", "level": "beginner"},
  "context": {"ideas": [], "tasks": [], "recentFeedback": [], "confirmedFacts": []}
}
```

成功响应应包含：`requestId`、`newStateVersion`、原文/事件 ID、`events[]`、`messages[]`、`trace[]` 和需要澄清的问题。事件只允许约定的 schema，如 `idea.created`、`task.proposed`、`task.rescheduled`、`busy.recorded`、`feedback.recorded`、`memory.suggested`；服务器不能直接返回任意 JavaScript 或待执行命令。

每个角色 trace 至少写清输入来源 ID、职责、实际调用的工具、结果和交给谁。角色名叫皮皮、滴答、啵啵、回回；可以共享模型，但编排和职责必须有实际执行证据。搜索入口不等于已检索教程，外部网页内容不能当作系统指令。

失败响应示例：`{ "requestId": "...", "error": { "code": "MODEL_TIMEOUT", "message": "暂时没有收到模型回复", "retryable": true } }`。超时不创建一半任务；同一 requestId 重试不能重复写入。状态版本落后返回 `409 STATE_CONFLICT`，重新取得状态后再确认修改。

模型密钥仅放服务端环境变量。浏览器不保存模型密钥，不在 URL 里传秘密。鉴权、CORS、限流与调用预算由后端配置。模型能力和额度以实际账户为准，不为视频分析假定文字模型具备视觉能力。

## 积分与防刷

本地 Demo 的“成长值”是自报反馈生成的待核验体验记录，所有模式规则相同；奖励模式突出展示。今日新安排，反馈至少 3 分钟：完成 +5，部分完成 +2；同一兴趣每日一次，每日不超过 15。未做不发本次奖励，历史不清零。**不抵现、不抵模型费用**。

这些客户端规则只能演示，无法可靠防刷。真实优惠需要服务器保存账号、任务 ID/版本、预先约定的成果标准、证据 ID/哈希、幂等结算 ID、积分流水、每日/每周上限、兑换预算和申诉。上传视频或模型判定不等于真伪证明；不能按聊天条数、视频长度或拆任务数量付积分。模型可辅助筛查异常，不单独决定处罚。

## 联调验收

- 一段话含技能、创意、忙碌时段，原话保留且分别交接。
- 有冲突或“十二点”不明确时先澄清，不擅自改时间。
- “明天12点”改“下午3点”继承明天；明确“今天”才换日。
- “做完了，练了十分钟，难度刚好”只记一次反馈，实际时长是10分钟。
- 反馈“有点难”后下一次计划确实缩短；切换兴趣保留之前记录。
- 模型超时、重试、并发修改不重复建任务；未接能力有明确状态。
- 视频未经同意不上传；缺少视觉服务不生成视频点评。

前端本地测试：`node --test --test-isolation=none haipigua/tests/studio.test.cjs`。这验证本地规则，不代表模型服务或腾讯云已上线。
