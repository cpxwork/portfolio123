# 给参赛者的演示小抄

## 打开与使用

在仓库根目录运行 `node haipigua/preview.cjs`，浏览器打开终端网址，默认 `http://127.0.0.1:8877/`。修改文件后刷新。GitHub 展示代码，这个网址展示可操作页面；它只在启动服务的电脑上可用。腾讯云生产网站需要发布负责人另行更新，不会因为 Git 提交自动改变。

首页直接输入完整碎碎念，按“递给皮皮”；Enter 发送，Shift+Enter 换行。不要先替系统分类。每段原话保留，点击“看看这次怎么理解的”检查规则是否理解对；理解错就继续说明。右上角选择今天的温和、奖励或督促方式。语音按钮需要浏览器支持和麦克风授权，不可用时用系统键盘语音输入。

“行动约定”看当前时间；“记忆口袋”修改已确认事实和默认时长、精力、基础，也能导出/导入文字备份。自由文字记忆目前仅作为记录，结构化偏好及历史反馈直接参与本地计划。视频可在反馈表单附上，25 MB 以内，本机保存回看，尚未分析；文字备份不包含视频原文件。

## 三分钟演示顺序

1. 先说问题：很多人不是没有计划，而是有许多碎片愿望；重复填表、计划不合生活、失败后难以重启。
2. 输入：“我想学画画，我是零基础，明天中午十二点试十分钟。明天上午九点到十一点有课。另外我想做一个给流浪小猫找家的小网站。”展示一段原话分给学习与创意。
3. 补充：“明天中午十二点到下午一点有课。”展示系统先追问。再说：“改到下午三点吧。”检查仍是明天。
4. 说明下面是模拟反馈，再输入：“画画只练了五分钟，有点难，因为线条总画不直。”展示回回交回皮皮。
5. 说：“画画后天中午十二点再练十分钟吧。”展示下次实际缩成六分钟，说明这条记录怎样改变安排。
6. 最后展示三种模式。虫虫先手动预览、一键清除。积分说清是不可兑换的本地体验，不把自报当成真实核验。

这是流程示范，不要把模拟反馈包装成真实用户成效。请以现场规则和实际可用模型服务为准。

## 怎样讲亮点

一句话：**嗨皮瓜把一段混杂的愿望，接成适合当下的一次行动；再让真实反馈改变下一次。**

三种模式是陪伴风格，不是给人贴“自律/懒”的标签。选择奖励的人多不用刻意惩罚来分流。除完成率，也记录继续使用意愿、反馈质量、计划修改次数、压力感与退出率；先作为待验证假设，别承诺提高多少效率。

四个头像本身不能证明多智能体。后端接上后，重点展示每个角色收到哪些信息、实际调用什么工具、写入了什么、为何交给下一位，以及失败后的恢复。不要宣称已具备目前没有的模型编排、真实教程检索、视频理解或永久记忆。
