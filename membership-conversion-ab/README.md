# 会员权益呈现与 A/B 实验方案

[查看／下载两页 PDF](membership-conversion-ab.pdf) · [PDF 生成源码](build_pdf.py)

**作品性质：AI 辅助产品设计练习。** 场景为假设的文件整理订阅工具，非百度内部项目。当前已产出静态页面方案、流程与异常验收、埋点和实验定义；没有真实用户、流量、线上实验或收益结果。

## 我想解决什么问题

假设免费用户点击升级后，可能因为不清楚免费与会员的差异、总价和续费规则而退出。这个假设尚未经过用户研究验证。本练习把它拆成可比较的页面方案和可核验的指标，避免直接把一次付费率变化解释为产品改进。

## 产品方案与 P0 范围

| 对照 A | 实验 B | 两组保持一致 |
|---|---|---|
| 权益逐项列出，保留基础信息层级 | 免费／会员权益并排对照，突出差异并调整组织和排序 | 实际权益、价格、支付能力、其他入口和确认按钮文案 |

两组都明确展示总价、期限和续费规则；B 只调整信息组织，不隐藏 A 组必要信息。P0 主流程为：**点击升级 → 方案页 → 确认订单 → 支付 → 权益到账**。

异常验收清单（方案要求，尚未在真实支付系统执行）：

- 取消支付可返回，失败可重试；自动续费须单独明确确认，不默认勾选。
- 重复回调必须幂等；扣款成功但权益未到账时显示“处理中”，提供查询与客服入口。
- 覆盖断网、延迟回调和重复请求，不能只验收成功页面。

## 分流与指标定义

对象为首次触发升级入口、尚未订阅的登录用户。在任何实验内容展示前，按账号稳定随机 50/50 分组，重复访问不换组；跨设备使用同一账号分组。匿名、跨账号或无法合并身份的行为另记限制。记录实际曝光和会话，曝光失败的用户仍保留在分母。

| 类型 | 口径 |
|---|---|
| 唯一主指标：7 日支付转化率 | 分母是全部已分组的合格用户（ITT）；分子是分组后 7×24 小时内至少有一笔服务端确认成功会员支付的用户，按账号去重。只计算观察窗已成熟的批次。 |
| 退款护栏：第 14 日快照 | 按每名用户分组后第 14 日取快照；分母为前 7 日成功支付用户，分子为其中截至快照发生退款的用户。更晚退款不在本次快照内；最终决策等待该护栏成熟。 |
| 其他护栏 | 支付错误、权益到账失败与投诉分别锁定分母、观察窗和容忍阈值。阈值需要真实历史基线，当前不虚构数值。其他行为指标只作诊断。 |

主指标统计成功支付，退款作为单列护栏，不把它误写为“7 日净付费转化率”。

## 埋点与严格诊断漏斗

事件：`eligible_assign`、`page_exposure`、`plan_select`、`checkout_create`、`pay_success`、`benefit_grant`、`refund_success`。

最少字段：去标识账号键、实验版本、会话 ID、订单 ID、业务事件 ID、事件时间和接收时间。先去重，再排查乱序、延迟和客户端漏报；支付以服务端状态为准。

诊断漏斗要求同一账号及对应会话／订单，按事件时间依次满足**曝光 → 选方案 → 建单 → 支付**，限定分组后 7 日并记录掉点原因。它与主指标 ITT 分开计算；“分别出现过各事件”的覆盖率查询不能作为严格漏斗，也不能替代随机实验的因果判断。

## 样本与决策规则

1. 用真实历史基线、最小可接受差异与功效估算样本，预先锁定样本量和周期，覆盖完整周并考虑新奇效应。当前没有基线，因此不填写虚构样本量。
2. 样本不足，按预设上限延长或报告不确定；达到样本量且相关观察窗成熟后统一判定。
3. 预注册一次双侧两比例主检验，稀疏数据采用预设精确检验；报告两组比例差与 95% 置信区间。
4. 不根据每日显著性提前结束。实验期间仅监控数据质量与护栏；只有预设护栏越界、分流异常或严重故障触发停机。
5. 修改方案后另开实验，不能用修改前后的混合数据宣称效果。当前没有真实实验结论或转化提升结果。

## 重新生成 PDF

已有 PDF 可直接阅读，无需运行源码。重新生成需要 Python 3.10+、ReportLab 和合法可用的宋体字体文件：

```bash
python -m pip install -r requirements.txt
python build_pdf.py
```

默认读取 Windows 的 `C:/Windows/Fonts/simsun.ttc`。其他系统可通过 `SIMSUN_FONT` 环境变量指定已有的宋体字体路径。脚本在本目录生成 PDF 和排版记录；仓库不附带字体文件。
