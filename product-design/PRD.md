# 指标管理平台产品需求文档

**性质：AI 辅助产品设计练习｜版本：0.1｜日期：2026-10-08**

本轮新创的模拟案例。所有业务、角色、样本数、负责人均是学习设定；没有开展真实访谈，没有企业在岗经历、正式开发团队或上线成果。文档提出的需求不是已投入生产的功能。

## 1. 问题与用户场景

假设一家提供付费订阅的在线学习产品，需要统一增长、交易和内容团队的指标。不同角色在报表中都写“付费转化率”，实际可能分别使用注册用户、活跃用户或首购用户作为分母。相同名称并不保证相同统计对象。

| 模拟角色 | 场景 | 当前风险 | 本练习提出的需求 |
|---|---|---|---|
| 产品/增长同学 | 比较新用户注册当天是否完成首购 | 把旧用户首购混入新注册用户转化 | 在指标名称和分子分母中明示人群、时间窗 |
| 运营同学 | 搜索“付费”、查看负责人和能否复用 | 只见数字，不知道来源、成熟时间和版本 | 可筛选目录，详情列出来源与口径 |
| 数据同学 | 修改定义后检查影响范围 | 更新分母但下游公式仍引用旧版本 | 展示依赖/下游关系，版本不一致时阻断最终展示 |

场景是设计假设，不以“访谈发现”表述。上线前若要验证，应向目标用户核实他们真实的搜索方式、争议口径与使用频率；本轮没有执行这些研究。

## 2. 目标、非目标与验证计划

**目标**：让使用者从目录找到正确指标、解释统计口径、识别不可比较的付费率，并在数据异常时看到明确状态和处理动作。

**本轮可验收交付**：一份需求文档、8 项完整指标定义、本地可操作原型、3 类异常处理与 12 条验收用例。

**不做**：真实数据库接入、生产 SQL 调度、企业权限系统、可视化看板、任意公式编辑、审批流后端、真实业务效果评估。

**后续验证计划，尚未执行**：请同学完成“找到新注册当日付费转化并解释分母”“找到净支付金额来源”“判断某指标为什么不可用”三项任务，记录成功/失败、用时与错误原因，反馈后再修改。没有基线前不承诺搜索效率提升或口径错误下降。

## 4. 数据模型与通用约束

**统一时间**：北京时间 UTC+8，自然日 D 为 `[D 00:00:00, D+1 00:00:00)`；订单归支付成功时间，不按创建时间。原型中时间戳使用带 `+08:00` 的 ISO 字符串。

**统一人群 E**：`users.is_test=false AND users.is_internal=false`，通过稳定用户 ID 关联。学习案例暂不覆盖游客、跨端用户合并、跨境时区和历史身份变更；若上线须另定规则。

| 逻辑表（无真实接入） | 最少字段 | 去重/边界 |
|---|---|---|
| users | user_id、registered_at、is_test、is_internal | user_id 唯一；用于人群与注册归属 |
| events | event_id、user_id、event_at、event_name | event_id 去重；有效活跃行为为 login、content_view、pay_success |
| transactions | record_id、order_id、user_id、record_type、occurred_at、amount_fen、status | record_id 去重；支付和退款分别为事件；金额以分为单位 |

**首次支付**：对 E 中每名用户，取全部可用历史里 `record_type=payment AND status=success AND amount_fen>0` 的最早 `occurred_at`。历史不完整则首购指标不可定稿，不能把窗口内第一笔误当人生第一笔。

**退款**：不抹掉已发生的首购事实；只按退款成功发生日冲减净支付金额。若业务需要“退款后有效购买用户”应另设指标，不能默默修改本定义。

**所有指标元数据**：ID、名称、业务域、类型、单位、口径、来源、上游ID、统计周期、刷新要求、负责人角色、版本、状态、使用场景。负责人是角色设定，不是实名组织。

## 5. 8 项指标数据字典

### M01 当日新注册用户数

- 业务域/类型/单位：增长 / 基础 / 人。
- 定义：E 中 `registered_at` 落在 D 的去重 user_id 数；无分母。
- 来源：users；粒度：自然日；版本：v1.0；负责人角色：增长产品。
- 刷新要求：D+1 09:00 前完成 D 的离线汇总；来源未完整时显示“数据延迟”。
- 用途/依赖：新注册队列规模；为 M04、M05、M06、M08 提供注册人群。

### M02 当日活跃用户数

- 业务域/类型/单位：内容 / 基础 / 人。
- 定义：E 中在 D 发生至少一次 login、content_view 或 pay_success 的去重用户数；无分母。
- 来源：users + events；粒度：自然日；版本：v1.0；负责人角色：内容运营。
- 刷新要求：D+1 09:00；事件尚未收齐时不定稿。
- 用途：描述行为活跃规模；不能作为新注册付费转化的分母。

### M03 当日新增首购用户数

- 业务域/类型/单位：交易 / 基础 / 人。
- 定义：E 中“全部历史最早成功且正金额的支付时间”落在 D 的去重用户数，包含更早注册用户；无分母。
- 来源：users + transactions；粒度：自然日；版本：v1.0；负责人角色：交易产品。
- 刷新要求：D+1 09:00，依赖历史支付完整；同用户多订单只计一次。
- 用途/依赖：衡量首购规模；为 M04 的注册队列交集提供首购条件。

### M04 新注册当日首购用户数

- 业务域/类型/单位：增长 / 派生 / 人。
- 定义：同时满足 M01 的注册条件和 M03 的首购条件的去重用户数；无分母。
- 依赖/来源：M01 + M03；users + transactions；版本：v1.0；负责人角色：增长产品。
- 粒度/刷新：自然日，D+1 09:00 且上游完整。
- 用途：把新增注册与新增首购取交集；不直接使用所有当日首购人数。

### M05 新注册当日付费转化率

- 业务域/类型/单位：增长 / 复合 / %。
- 分子：M04；分母：M01；公式：`M04 / M01 × 100%`，分母为 0 返回空值并显示“无可计算样本”，不返回 0%。
- 依赖/来源：M04 + M01；users + transactions；版本：v1.0；负责人角色：增长产品。
- 粒度/刷新：注册队列 D；D+1 09:00 后上游齐备才最终展示。
- 用途：衡量注册当天的首次付费转化；不代表后续累计转化。

### M06 新注册次日留存率

- 业务域/类型/单位：增长 / 复合 / %。
- 分子：M01 的 D 注册队列中在 D+1 有 M02 所定义有效活跃行为的去重用户数；分母：M01(D)。
- 来源/依赖：users + events；M01 与 M02 的活跃规则。版本：v1.0；负责人角色：增长产品。
- 公式：分子 / M01(D)；分母为 0 时空值。
- 粒度/成熟：注册队列 D；D+2 09:00 后完整观察与数据汇总才定稿。
- 用途：评价首次使用后翌日再次行为；不使用 D+1 全体活跃人数作分子。

### M07 当日净支付金额

- 业务域/类型/单位：交易 / 派生 / 元。
- 定义：E 中 D 发生的成功正金额 payment 之和，减去 D 发生的成功 refund 金额之和。退款可以对应往日订单；因此当日净额允许为负。
- 来源：users + transactions；record_id 去重；支付/退款实际发生时间归日。版本：v1.0；负责人角色：交易产品。
- 粒度/刷新：自然日，D+1 09:00；金额从分换算元，展示保留两位小数。
- 用途：支付流水净额；不是财务收入确认、GMV或现金会计报表。

### M08 新注册7日首购转化率

- 业务域/类型/单位：增长 / 复合 / %。
- 分子：M01 的 D 注册队列中，全部历史首次支付发生在 `[D 00:00, D+7 00:00)` 的去重用户数；分母：M01(D)。
- 来源/依赖：users + transactions；M01 和 M03 的全历史首购规则。版本：v1.0；负责人角色：增长产品。
- 成熟：观察完整覆盖注册日及其后 6 个自然日，D+7 09:00 且数据齐备才定稿；之前显示“观察中”，不是最终转化率。
- 公式：分子 / 分母；分母 0 返回空值。
- 用途：与 M05 区分当天与7日转化；两个不同成熟队列不能直接比较。

## 6. 付费口径争议案例

下表是人为设定的示例数据：某日新注册 1,000 人、活跃 2,000 人、当日新增首购 160 人，其中当日新注册且首购 80 人。

| 名称 | 计算 | 示例值 | 可以解释什么 |
|---|---|---|---|
| 新注册当日付费转化率（M05） | 当日注册且首购 80 / 当日注册 1,000 | 8.0% | 新注册队列当天首购比例 |
| 活跃用户首购占比（对比示意，未列入8项目录） | 当日新增首购 160 / 活跃 2,000 | 8.0% | 活跃中的首购比例，需确认首购包含于活跃行为范围 |
| 首购中当日新注册占比（对比示意，未列入8项目录） | 当日注册且首购 80 / 当日新增首购 160 | 50.0% | 首购用户的注册时间构成 |

前两项碰巧相等，不能由数值相等推断口径相同。三个比例不应用同一个指标 ID 或互相替代。

决策：增长场景默认使用 M05；页面名称完整展示“新注册”“当日”“首购”，并固定分子/分母与时间窗。若需要其他人群比例，创建新指标，不修改 M05 的分母。

## 7. 原型与关联

**目录**：搜索框匹配名称、ID、标签与负责人角色；业务域与类型为 AND 条件；空结果提供清空入口。点击指标查看定义、来源、版本、直接上游及直接下游。

**关系**：M01、M03 → M04；M01、M04 → M05；M01、M02 → M06；M01、M03 → M08。M07无目录内上游，但保留来源表。M06 对 M02 是“规则依赖”而不是把 M02 的总人数代入分子；M08 对 M03 是首购判定规则依赖，不能累加每日首购总数替代队列计算。

原型关系展示注明“规则依赖”与“数值依赖”；本轮为预置直接关系，不是自动解析任意 SQL，也不做完整递归血缘治理。

## 8. 3 类异常

| 类别 | 触发 | 展示与产品动作 | 验收关键 |
|---|---|---|---|
| A1 分母为零 | M01=0 | 结果为空，标签“无可计算样本”；说明当天没有符合范围的新注册用户 | 不能显示 0%、Infinity 或 NaN |
| A2 源数据延迟 | 指标已到可定稿时间，但任一上游尚未完成汇总 | 显示“数据延迟”，不展示本期最终值；显示需要补齐的上游/刷新要求 | 不能把旧日期数值标成本日有效值 |
| A3 口径版本不一致 | 指标要求的上游版本与实际版本不同 | 显示“口径待复核”，阻断正式对比与导出最终值；列出冲突依赖 | 不能按未知版本继续计算 |

多个异常并存时先说明版本冲突、再说明数据延迟、最后解释样本为空；一个异常解除不能掩盖其他异常。本地原型一次模拟一种异常，复合状态属于后续实现范围。

| ID | 操作/给定条件 | 预期结果 |

## 10. 发布与面试使用条件

文档/原型是本轮产出，可展示需求推理与学习过程。作者需亲自跑一遍AC01—AC12，逐条检查定义能否被自己解释，并修改不认可的取舍。未经真实业务验证，简历只描述学习交付数量，不能声称口径错误下降、效率提高、真实上线或完成企业指标治理。
